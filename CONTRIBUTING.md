# Working together

## Roles
- **Builder:** game code in `game/`.
- **Designer:** mockups, art, game balance in `docs/game-design.md`.
- **Presenter:** pitch, demo video, business model.
Everyone helps whoever is stuck.

## Workflow
1. Pick an Issue and assign yourself.
2. Create a branch: `feature/<short-name>` (for example `feature/engine`).
3. Make small commits with clear messages, e.g. `Add solar storm event text`.
4. Open a pull request. Someone else reviews it before it is merged into `main`.

## Rules
- Do not commit secrets or `.env` files.
- Every science fact needs an official source listed in `CREDITS.md`.
- Game values (probabilities, costs) must be labeled as design values, never as NASA data.
- Take a 5-minute break when blocked. Slow and safe beats fast and broken.
